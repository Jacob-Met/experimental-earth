# See which adjacent rainfall totals can coexist

Separate ranges can hide a shared constraint. When minutes 0–10 contain exactly 10 mm, each five-minute half can separately contain anywhere from 0 to 10 mm. But the two totals must add to 10: choosing 6 mm for both halves is impossible.

This tool returns the exact joint attainable region for two adjacent declared intervals under the original calibration readings. Let **x** be rainfall from start to split and **y** rainfall from split to end. The output describes all possible pairs, with source-constraint proofs and constructive histories. It does not infer actual rainfall or assign probabilities.

## Three fictional examples

Use one query declaring minutes 0, 5, and 10:

```sh
node inspect-rainfall-joint-region.mjs examples/conditional-rainfall-original.json examples/rainfall-joint-region-query.json
node inspect-rainfall-joint-region.mjs examples/rainfall-joint-region-hexagon-original.json examples/rainfall-joint-region-query.json
node inspect-rainfall-joint-region.mjs examples/rainfall-joint-region-unbounded-original.json examples/rainfall-joint-region-query.json
```

The first reuses the unchanged fictional whole-interval 10 mm original. Its expected region is the **segment** from (0,10) to (10,0), with no recession rays. The pair (6,6) lies outside it even though each coordinate belongs to its separate marginal range.

The second supplies fictional calibration bands of 1–4 mm for each half and 3–7 mm for the whole interval. Its expected region is a **bounded hexagon**, with lexicographically ordered vertices (1,2), (1,4), (2,1), (3,4), (4,1), and (4,3). Vertex order is by x then y, not traversal around the polygon.

The third has no calibration readings. Its fictional challenge-only reading remains held aside. The expected region is the **nonnegative quadrant**: vertex (0,0) and rays (1,0), (0,1). No intensity ceiling or storm cutoff limits these mathematical possibilities.

All three actual commands returned the geometries above. An independent exact-rational oracle derived the six constraints from each original and checked complete vertices, rays, classifications, paths and histories. Seven focused tests passed, including original contradiction, degenerate geometry, excluded evidence, represented units, subnormal times, admission and the maximum work reservation. All source, input, runtime and control identities held unchanged through both bounded courses. All example readings and questions are authored controls, not acquired observations.

## Declare adjacent intervals

The query has exactly six fields:

```json
{
  "schema": "experimental-earth-rainfall-joint-region-query/1",
  "eventRef": "authored full-family arithmetic event",
  "startMinute": 0,
  "splitMinute": 5,
  "endMinute": 10,
  "source": "Authored fictional adjacent-interval question; not measured rainfall"
}
```

The event reference must exactly match the original gauge. Times must satisfy `0 <= startMinute < splitMinute < endMinute <= durationMinutes`. Event reference and source must be nonblank strings of at most 600 characters. Matching declarations do not establish that event, site, or clock associations are physically correct.

Only calibration readings constrain this region. Original challenge and unassigned readings remain in the full original and explicit exclusion list. No hypothetical condition is introduced, and no evidence role is changed. The original project and gauge are validated; other proposal context is retained without being evaluated or qualified.

## Interpret the region

The CLI returns `experimental-earth-rainfall-joint-region-cli/1`, original/query byte lengths and SHA256 identities, and a report with schema `experimental-earth-rainfall-joint-region/1`. The report preserves the complete original and query, the unchanged calibration-only assessment, work reservation, and joint assessment.

A feasible region contains exactly six ordered inequality slots: early lower/upper, late lower/upper, and whole lower/upper. Each finite slot includes exact coefficients, a rational right-hand side, and a connected path of original constraints proving the inequality. An unreachable bound uses `status: unbounded` with null right-hand side and path, never `Infinity`.

The region equals **the convex hull of its vertices plus the cone generated by its rays**. Each vertex includes an attaining nonnegative history and original calibration interval checks. Each ray includes a direction history with zero increment over every calibration interval and the stated increments over the two queried intervals. Its reachable-vertex field is the union of reachability from all three interval anchors, not one anchor alone.

Dimension and classification distinguish a point, segment, ray, bounded region, or unbounded region. A vertex list is lexicographic; consumers must not treat it as polygon boundary order. The original-calibration-inconsistent status instead returns no region and a verified connected negative cycle. That certificate is not claimed to be a minimum conflict or a diagnosis of a faulty instrument.

Exact histories prove attainability within the constraints; they are not unique, inferred, or observed physical rainfall. Segment rates are checked against their own durations, and interval totals use cumulative endpoint differences. No soil, depth, intervention, finite-family restoration, or probability conclusion follows.

The estimator admits inputs and reserves complete work without invoking a solver. The consumer calls the unchanged calibration assessment once, solves original feasibility once, and, when consistent, makes three source-rooted shortest-path calls. The CLI accepts regular non-symlink files, verifies their identities and bytes after analysis, and writes its complete result to stdout without changing inputs.
