# Original raster elevations in the site model

The existing terrain section now accepts ESRI ASCII elevation grids. Open **Import an elevation raster (.asc)**, choose an original file, identify its source and coordinate reference, and declare its horizontal and elevation units. The header supplies grid dimensions, spacing and lower-left origin. Select the original upper-left row and column of the window to use; the window has the same dimensions as the current site.

Preview reads every selected original sample directly. No per-cell CSV transcription, resampling, missing-cell interpolation or coordinate reprojection is performed. Source spacing must equal the site's cell width after the declared unit conversion. The first selected sample is proposed as the local zero; an optional original-unit reference replaces it. Use a consistent vertical reference for compared plans and any declared barrier crests. The model accepts local heights between −10 and 10 metres.

Apply to the existing site, proposed site, or both. Surfaces, notebook readings and other settings remain present. The ordinary comparison immediately uses the imported terrain. Check that retained measurements and geometry declarations still describe that place. Inspecting a cell shows its original raster row, column, physical source line, value, source coordinates, coordinate-reference declaration and local zero. Export/reopen retains those records and the SHA-256 identity of the supplied file. The hash identifies supplied bytes; it does not authenticate their author or physical accuracy. The original full raster is not embedded in each project; retain it to reproduce acquisition.

## Format and supported bounds

The [Esri format specification](https://help.arcgis.com/en/arcgisdesktop/10.0/help/009t/009t0000000z000000.htm) defines top-to-bottom row order, matching lower-left corner or center coordinates, and an optional NoData sentinel (default −9999). Data can wrap across physical lines independently of raster rows. The reader follows those rules, accepts case-insensitive header keywords and finite decimal/scientific-notation values, and requires exactly the advertised sample count. Duplicate or inconsistent headers, non-ASCII data, nonfinite values and trailing samples refuse.

Original inputs are bounded to 8 MiB and 1,048,576 samples; the current site remains 2–24 cells on each axis. Larger regional DEMs require a bounded exported source window before browser intake. Horizontal/elevation units are explicitly metres, centimetres or millimetres. A geographic degree grid must first be appropriately projected outside this reader; selecting a metre unit is a supplied declaration, not inferred georegistration. Selected NoData refuses the whole preview; NoData outside the requested window does not become invented terrain.

ASCII grids do not provide per-cell measurement uncertainty. The new `rasterSource` record therefore stays distinct from surveyed `terrainSource` intervals. Existing surveyed uncertainty investigations keep their original eligibility; no zero-error measurement is invented. Original file metadata and samples survive portable project validation. Changing a height with the ordinary brush removes only that cell's obsolete origin. Replacing a raster with a supplied survey (or the reverse) retires the former elevation source. Solar evidence binding includes raster custody when present, preserving legacy contexts when absent.

## Executed receiving inputs

`tests/terrain-raster.test.mjs` checks independently calculated asymmetric coordinates, corner/center equivalence, physical line wrapping, original byte identity, unit conversion, NoData, malformed sources, stale asynchronous previews, changed maintained rain results, reopen validation and source replacement. `tests/terrain-raster.receiving.mjs` exercises the actual application, file input, both-grid application, original-source inspector, real project download and reopening, narrow-screen keyboard access, missing-source refusal and height-edit retirement.

The [USGS source window](../examples/usgs-ds684-window/source.json) is a separately acquired historical terrain input. Its 48 original values come from the public [North-Central California Coast DEM](https://pubs.usgs.gov/ds/684/ds684_metadata/NCenCA_DEM_FGDCmetadata.html), original rows 4–9 and columns 4800–4807. The upstream ZIP SHA-256 and unmodified sample tokens are retained; only the derived window's dimensions/origin differ. USGS supplies 2-m spacing, NAD83 / UTM zone 10N coordinates and NAVD88 elevations. The full 412,580,611-byte ASCII file is outside this browser reader's support envelope. The selected window proves a real dataset can drive the maintained consumer after explicit source-window preparation; it does not prove direct full-region ingestion, current conditions, calibrated infiltration or environmental prediction accuracy.

Run `node tests/terrain-raster.test.mjs` and `CHROME_BIN=/opt/google/chrome/chrome node tests/terrain-raster.receiving.mjs`. Browser receiving uses the maintained isolated Chromium session and sandbox check. Screenshots and source-received projects are written into that run's directory.
