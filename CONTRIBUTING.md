# Contributor guidance

## Choose useful work through existing coordination

Read the [product seed](docs/PRODUCT_SEED.md), actual source, issues, pull requests and [HAMON shared priority board](https://github.com/Jacob-Met/hamon/issues/1354). Use the existing native claim mechanism, respect active ownership and coordinate overlaps directly. Do not create another task system or reassign other teams. Choose a concrete product improvement, not activity for its own sake. The seed invites additional capabilities and better approaches; it is not a closed backlog.

## Build verify integrate continue

Implement coherent runnable improvements and test the difficult transformation they claim. Use meaningful local or native tests and proportionate independent review. GitHub Actions being unavailable does not prohibit verified progress. Record exact source, relevant inputs, commands, results and limitations; distinguish physical observations, model estimates and authored simulation.

Run independent reads and tests in parallel when useful. Order dependent operations: inspect before changing, test before claiming qualification, and verify the result of a mutation before making a dependent one. Reconcile uncertain external writes before retrying them.

Merge qualified changes through the supported process, respecting required reviews and branch protection, then verify the maintained branch. After delivery, immediately select **and begin** the next useful authorized improvement in the same execution. Update results and evidence-grounded follow-ons briefly, release or transfer claims correctly, and leave enough context for continuation. Do not wait merely for a report response or a new scheduled invocation. This is continuing contribution, not a promise of uninterrupted runtime.

## Reuse and investigate without creating a platform gate

Coordinate with existing geometry, reconstruction, simulation and active-learning owners. Reuse qualified HAMON Engine or estate components; return useful shared extensions with actual consumer evidence. Do not force a whole-platform migration or wait for a perfect shared system before making independent progress. Compare suitable alternatives, retain negative findings and integrate what genuinely helps.

## Stay within authorization and state evidence honestly

Use available authorized tools, accounts and environments. Do not expand access, publish private source or data, change licensing, incur new costs, submit entries or perform physical interventions without the relevant authorization. Never commit credentials.

The [official Nebius rules](https://nebiusglobalaihackathon.devpost.com/rules) guide contest qualification, not the limit of the product. Demonstrate genuine runtime platform and model contribution when integrated; unavailable provider access does not erase other useful work. Do not claim scientific validity from an attractive simulation or agreement with its own generated data. Keep uncertainty visible while continuing to improve the experience.
